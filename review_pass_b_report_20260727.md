# Review pass B — отчёт

## Исправленные реальные проблемы

1. `vision/prompt_to_bitmap.py:69,95,112,129,193,230` — на грубых сетках
   цветная заливка исчезала: сердце, звезда, абстракция и мордочка на 4x4
   становились только чёрными; абстракция на 8x8 и солнце с горами на 20x20
   также могли исчерпать лимит одними контурными ячейками. Укрупнены заливки,
   разрозненные элементы объединены в связные области, абстракции добавлена
   базовая цветная плоскость.

2. `agents/llm_client.py:220-266` — валидный пустой массив задач трактовался как
   отсутствие данных и заменялся выдуманной задачей A1. JSON-массив теперь
   извлекается через `JSONDecoder.raw_decode`, а `[]` сохраняется.

3. `agents/llm_client.py:156-186` — несмотря на комментарий о запрете повторов,
   seed=2 воспроизводил одинаковые реплики Академиста подряд. Добавлена память
   последней строки отдельно для каждой личности.

4. `agents/dialogue_engine.py:139-205` — `recolor` принимал произвольную строку
   и мутировал уже созданный `PaintTask`, обходя `__post_init__`; fallback мог
   вернуть невалидный объект. Цвет теперь проверяется по `COLORS`; бесконечная
   длительность также не принимается.

5. `agents/dialogue_engine.py:213-237,400-408` — пустой `cells` координатора
   ошибочно считался невалидным, а несуществующие ячейки координатора
   принимались и позже могли уронить `CanvasGrid.cell_to_world`. Пустой план
   разрешён, неизвестные координатору ячейки фильтруются по рабочему плану.

6. `agents/dialogue_engine.py:53-83,352-358` — бюджет проверялся только между
   синхронными вызовами; один LLM-вызов с HTTP timeout 20 с мог нарушить бюджет
   2 с, после чего всё равно вызывался координатор. Добавлен deadline-aware
   daemon-вызов и возврат рабочей копии после исчерпания общего времени.

7. `agents/dialogue_engine.py:86-110` — vision и офлайн-координатор оставляли
   все `priority=0`, поэтому сортировка `conflict_scheduler` по priority была
   фактически бесполезна. При полностью нулевых приоритетах назначаются
   стабильные ранги: чёрный контур первым как регистрационная направляющая,
   затем заливки.

## Проверки без найденного бага

- Патч агента на отсутствующую ячейку уже игнорировался; добавлена регрессия.
- `Broadcaster` уже создавал глубоко вложенные каталоги через `os.makedirs`,
  а `log_path=None` корректно отключал файловый вывод.
- `mission_runner.py` не изменялся. Пустой итоговый план обрабатывается:
  цикл координат пуст, `schedule([])` возвращает `[]`, `run_schedule([])`
  создаёт нулевые отчёты; затем выполняется формальный взлёт и посадка.
- `run_dialogue(rounds=3, time_budget_s=2.0)` с офлайн-клиентом завершился за
  0.0032 с. Дополнительный блокирующий клиент проверен с бюджетом 0.15 с.
